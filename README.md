CheckStock

Одномагазинный прототип учёта остатков на складах фулфилмента, резервов FBS и товаров в пути. FastAPI обслуживает JSON API и интерфейс, PostgreSQL хранит данные. Интерфейс работает в браузере без сборки.

## Запуск

Если установлен Docker с Compose, выполните в папке с файлом `compose.yaml`:

```sh
docker compose up --build
```

Откройте [CheckStock](http://127.0.0.1:8000). Документация API доступна [в Swagger UI](http://127.0.0.1:8000/docs). При первом запуске в пустой базе автоматически создаются склады «Север» и «Юг», три артикула и четыре тестовых прихода из задания.

### Ручной запуск в Windows PowerShell

Нужны Python 3.10 или новее и уже запущенный PostgreSQL. Откройте PowerShell в папке, где лежит `requirements.txt`. Если распаковали ZIP, эта папка может находиться на один уровень глубже.

**1. Создайте виртуальное окружение.** Сначала выполните `py -3 --version`. Если команда выводит версию Python 3.10 или новее, выполните:

```powershell
py -3 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
```
```
**2. Один раз создайте пользователя и базу.** Подключитесь к PostgreSQL администратором. В примере используются стандартные порт `5432`, роль `postgres` и путь установки PostgreSQL 17. Если ваша установка отличается, замените их на свои. При запросе введите пароль администратора.

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\psql.exe' -h 127.0.0.1 -p 5432 -U postgres -d postgres -W
```

В приглашении `psql` выполните команды по порядку. Команда `\password` дважды запросит новый пароль для `checkstock_app`. База создаётся с этим пользователем в качестве владельца.

```sql
CREATE ROLE checkstock_app LOGIN;
\password checkstock_app
CREATE DATABASE checkstock OWNER checkstock_app;
\connect checkstock
GRANT USAGE, CREATE ON SCHEMA public TO checkstock_app;
\quit
```

Если база и пользователь уже созданы, используйте их имя, пароль и порт на следующем шаге.

**3. Запустите приложение.** В PowerShell выполните блок ниже. Введите пароль `checkstock_app`, который задали на предыдущем шаге. Если PostgreSQL слушает другой порт, измените `$dbPort`.

```powershell
$dbPort = 5432
$credential = Get-Credential -UserName 'checkstock_app' -Message 'Введите пароль PostgreSQL'
$dbUser = [Uri]::EscapeDataString($credential.UserName)
$dbPassword = [Uri]::EscapeDataString($credential.GetNetworkCredential().Password)
$env:DATABASE_URL = "postgresql://${dbUser}:${dbPassword}@127.0.0.1:${dbPort}/checkstock"
& '.\.venv\Scripts\python.exe' -m uvicorn app.main:app
```

Дождитесь сообщения `Application startup complete` и откройте [CheckStock](http://127.0.0.1:8000). Сервер работает, пока открыто окно PowerShell. Для остановки нажмите `Ctrl+C`.


## Как устроен учёт

- Доступный остаток на ФФ равен физическому за вычетом резерва. При создании резерва физический остаток сохраняется. Отправка FBS уменьшает и физический остаток, и резерв, отмена снимает резерв. Подтверждение доставки закрывает движение к клиенту.
- Перемещение и отправка FBO сразу уменьшают остаток склада-источника. Приёмка между ФФ увеличивает остаток склада назначения. Приёмка FBO закрывает движение, поскольку остаток на площадке находится за границей учёта складов ФФ.
- При нехватке API возвращает конфликт и показывает доступное количество на выбранном ФФ и на других действующих складах. Менеджер сам выбирает источник или оформляет перемещение.
- Удаление переводит склад в архив с сохранением физического остатка, резервов и истории. С него можно вывезти свободный товар на действующий склад. Уже созданные резервы и перемещения можно завершить, включая приёмку отправленного до архивации товара.
- Изменение остатков, статуса и запись события проходят в одной транзакции. Для одного магазина прототип последовательно выполняет записи через транзакционную advisory-блокировку PostgreSQL. Ограничение таблицы защищает условие `0 ≤ резерв ≤ физический остаток`. Чтение сводки использует единый снимок данных.
- Клиент передаёт UUID при создании операции. Повтор с тем же UUID и параметрами возвращает существующую операцию. Подтверждение сверяется с журналом по паре «операция, действие». Повтор возвращает текущий статус без повторной записи движения или изменения остатка.


## Границы прототипа

Один магазин и фиксированный справочник из трёх товаров. Маркетплейс и клиент представлены как направления движения, а подтверждения вносит менеджер вручную. Интерфейс рассчитан на локальную демонстрацию.
